# 队列与现实一致性复核（每 20 次会谈做一次）

按 MEMORY_POLICY §5。逐条执行，每条写下结论，不凭印象。

## 1. threads.md
- [ ] 每个 `open` 项：在更晚的 session 里是否已经解决了？解决了就改 `done`，并写依据 session 号
- [ ] 超过 90 天无进展：`stalled` → `archived`，并在对应 session 记一句为什么
- [ ] 有没有同一件事挂着两条 id（重复会让 agent 重复提起）
- [ ] **有没有一条被反复提起、他每次都答应但从未做的事？**这类条目要单独写出假设并进 `insights.md`，不要再当待办反复催

## 2. signals.md
- [ ] 每个 `unresolved` 项：本轮要不要提？（提 = 有自然入口，不提 = 继续留着，两者都要记录）
- [ ] 有没有历史条目已经在事实上过时、但仍可能被检索出来当作现状引用
- [ ] 迁移/汇总类断言（如"未检索到自伤表述"）是否带着**检查日期和有效期**？没有就补

## 3. profile.md
- [ ] 只复核会变的部分：工作、节奏、目标、市场/薪资口径
- [ ] 每条都有 `src:` 出处？没有出处的条目 = 污染，重新确认或删到 insights
- [ ] 有没有把我的推测当成他的事实写下来了？→ 移到 `insights.md`

## 4. no_repeat.md
- [ ] 最近有没有第二次犯同一个错？→ 说明那条规则写得不够具体，改写成"禁止 + 替代动作"
- [ ] 「待观察」区里有没有已经被证实的？→ 升级为规则

## 5. insights.md
- [ ] 每条假设：这 20 次里有没有新的支持或反证？更新 `last_seen`
- [ ] 被推翻的标 `overturned` 并保留（保留比删除有用，能防止同样的假设再来一遍）

## 6. 分层检查（最容易腐化的地方）
- [ ] `AGENT.md` 里有没有混进关于这个人的具体信息？
- [ ] `knowledge/` 里有没有混进来访者事实？
- [ ] `memory/` 里有没有出现凭据、内网入口、第三方可识别信息？→ 立即剔除并按 §6 记录

## 7. 趋势（写给下一次的我）
用 3–5 句写：这段时间他的主线是什么，我的哪种回应明显有效，哪种明显让他退开。
不要写成评估报告，写成给下一个自己的便条。
